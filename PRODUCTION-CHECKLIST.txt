 4. YOUR DOMAIN — THE ONLY UNAVOIDABLE SPEND
--------------------------------------------------------------------------------
 Reality (researched, 2026): a genuinely FREE "real" domain with no limits and
 no expiry does not exist for anyone. ICANN charges a mandatory annual fee per
 domain; Freenom (the famous .tk/.ml free registrar) was shut down over
 abuse. Every "free forever" domain today is a subdomain on someone else's
 property that can be revoked or capped (your work.gd is exactly this).

 What you own right now, free forever with no expiry:
     https://thecyberexpert123-stack.github.io/3Dwebsite/   ← the real home
 Hosting is permanently solved (GitHub Pages). You are only ever paying for
 the NAME string.

 Realistic cost (renewal price is what matters):
     Cloudflare Registrar   — at-cost; cheap TLDs ~₹250–300/yr, .com ~₹900/yr
     .in from Indian registry paths — roughly ₹500–900/yr
     Namecheap / Porkbun / GoDaddy promos — first year cheap, renewal higher

 Recommendation: buy a real domain (e.g. whimlet.in, whimlet.com) and point it
 at GitHub Pages. Everything else in your stack can stay free forever.

 5. REMOVING BLOCKER (A): MAKE GOOGLE VERIFY YOUR APP
--------------------------------------------------------------------------------
 Once you own a domain, the road is mechanical. Mark each box as done.

 [ ] 5.1  Buy the domain at the registrar of your choice.
 [ ] 5.2  In GitHub: repo Settings → Pages → Custom domain → type the domain.
          (This writes/needs a CNAME record — see next step.)
 [ ] 5.3  In your registrar's DNS panel add:
              CNAME  whimlet.<tld>  →  thecyberexpert123-stack.github.io
          (or, if it insists on A records, the 4 GitHub Pages IPs below, but
           CNAME is preferred for a subdomain.) Do NOT use www unless you want
           the site on www.whimlet.<tld>.
 [ ] 5.4  GitHub Pages → re-check "Enforce HTTPS" and wait for the cert
          (usually a few minutes).
 [ ] 5.5  Google Search Console → add the domain → verify via DNS TXT record
          (your registrar gives it to you; paste it as a TXT record). This is
          THE step that lets Google verify you. No free subdomain can do this.
 [ ] 5.6  Google Cloud Console → OAuth consent screen → swap all URLs to
          https://whimlet.<tld>/..., add whimlet.<tld> to Authorized domains.
              Home page            https://whimlet.<tld>/
              Privacy policy       https://whimlet.<tld>/privacy/
              Terms of service     https://whimlet.<tld>/terms/
 [ ] 5.7  (If asked) Submit the app for brand verification — with non-sensitive
          scopes there is NO paid CASA security review; this is just the
          domain/brand check.
 [ ] 5.8  Supabase → Authentication → URL Configuration → Redirect URLs: add
              https://whimlet.<tld>/**
 [ ] 5.9  Supabase → Authentication → Providers → Google → confirm the client
          and callback remain correct; the browser returns to
          https://whimlet.<tld>/signin.
 [ ] 5.10 Tell the agent the final domain. Code-side, the agent then:
              - sets NEXT_PUBLIC_BASE_PATH="" and
                NEXT_PUBLIC_SITE_URL=https://whimlet.<tld> in
                .github/workflows/deploy-pages.yml
              - adds the CNAME file for GitHub Pages
              - re-checks canonical URLs, sitemap, robots, OpenGraph
          (These are build-time values — they cannot be changed by you in a
           dashboard; they are code changes on the branch.)

 Result: consent screen shows with NO warning; the ~100-user cap disappears;
 the "unverified app" banner goes away.

   - 2 active projects
   - AUTO-PAUSES after 7 days of API inactivity. GitHub Pages traffic does NOT

   - NO automated backups / point-in-time recovery.
   - Built-in mailer: ~2 emails/hour, unbranded, limited template editing.

 Decision table:
   STAY FREE                         → cost ₹0. Accept the pause + no backups.
                                       Adopt the weekly hygiene habit below.
   SUPABASE PRO (~USD 25/month)      → always-on (no pause), automated daily
                                       backups + PITR. (If you upgrade, do it
                                       within 7 days of a pause to reclaim the
                                       data.) Recommended for a real store.

 Weekly hygiene if you STAY FREE (5 minutes):
   [ ] Open https://supabase.com/dashboard → your project.
   [ ] If it shows PAUSED, click Restore and wait ~2 minutes.
   [ ] If you upgraded to Pro later, this habit becomes unnecessary.

 Email delivery — do this regardless of tier:
   [ ] Confirm Brevo custom SMTP is actually ENABLED in Supabase →
       Authentication → Emails → SMTP (you followed supabase/README.md).
       Values: host smtp-relay.brevo.com, port 587, username = your SMTP Login,
       password = the generated SMTP key (shown once), sender = verified.
       This removes the 2-emails/hour ceiling that would otherwise silently
       drop verification emails on a busy day.

 10. ADMIN RUNBOOK (keep this somewhere safe)
--------------------------------------------------------------------------------
   The model: there are NO separate admin credentials. "Admin" is a claim on a
   normal Supabase Auth account. The boundary is the DATABASE (RLS), not the
   UI. A customer who guesses /admin is refused by the database even if the
   page paints.

   Add a new admin (the agent cannot reach your project — you run this):
     1. Have the person sign in once at /signin (creates + verifies account).
     2. In Supabase → SQL Editor run, with their exact email:
            update auth.users
               set raw_app_meta_data = raw_app_meta_data || '{"user_role": "admin"}'
             where email = 'legitanusuya@gmail.com';
     3. They sign out and back in → menu shows "Admin", /admin opens.

   Remove an admin: set user_role back to customer (or null):
            update auth.users
               set raw_app_meta_data = raw_app_meta_data - 'user_role'
             where email = 'someone@gmail.com';

   Hidden door (bookmark it, never link it publicly):
            https://thecyberexpert123-stack.github.io/3Dwebsite/owner
     It is unlisted, noindex, robots-disallowed. Its secrecy is discretion,
     not security — the lock is the claim + RLS.
